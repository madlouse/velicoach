# 评分维度与底线

## 评分锚点（1–5）

- 1：有明显问题，影响理解或使用
- 2：能用，但一眼可见是默认值或模板
- 3：合格、整洁，但普通
- 4：专业，能看出每个决定都是有意为之
- 5：令人印象深刻，而且服务于概念，换到别的项目里就不成立

每个分数都要附证据（哪张截图、哪个位置，或者一个测量值）。

## 参照的评审体系

- **Awwwards**：设计 40%、可用性 30%、创意 20%、内容 10%。设计和可用性加起来占七成，炫目但难用的作品拿不到高分。
- **FWA**：更看重创新和交互体验，偏实验性。
- **Apple Design Awards**（App）：Delight and Fun、Inclusivity、Innovation、Interaction、Social Impact、Visuals and Graphics。

按项目性质选择参照：商业官网和报告页更接近 Awwwards 的权重，实验性品牌站可以参考 FWA。

## 通用维度

### 第一印象
- 只看第一屏，能说出“这是什么、对我有什么用、下一步做什么”
- 有一个主导对象，阅读路径稳定
- 眯眼测试：模糊看，层级仍然清楚；把文字遮住，身份、强调、分组和顺序仍然能看出来

### 排版
- 字号阶梯一致，同级元素共用同一角色
- 西文正文行长 60–70 字符；中文正文每行约 25–40 字
- 中文行高 1.6–1.8；标点挤压合理；中西文之间有间距；避免行首标点和孤字成行
- 标题用 `text-wrap: balance`，长段落用 `text-wrap: pretty`
- 中文字体做子集化或使用系统字体栈，避免首屏加载数 MB 的字体

### 版式与留白
- 所有间距来自间距阶梯，每个间距只有一个负责的容器
- 组内近、组间远、章节转换更远
- 空白有目的；分栏没填满或孤零零的第三项造成的大块空白，算作版式问题

### 层级
- 每屏一个主 CTA
- 层级首先靠字号和字重，其次才是颜色和容器

### 色彩
- 文本对比度 ≥ 4.5:1，大字 ≥ 3:1
- 颜色有语义角色，不靠颜色单独传达信息
- 深色模式单独校对

### 动效
- 每个动效都有目的：引导、反馈、保持连续或叙事
- 界面级动效 150–400ms
- 支持 `prefers-reduced-motion`；不劫持原生滚动；阅读不需要等动画

### 微交互
- 所有可交互元素都有 hover、focus-visible、active、disabled 状态
- 键盘可完成所有操作
- 操作后 100ms 内有可见反馈

### 响应式
- 320–1920 宽度内无横向滚动
- 移动端是重新编排，不是桌面的缩小版
- 移动端触控目标 ≥ 44×44px

### 原创性
- 有一个能追溯到概念的签名时刻
- 没有出现未经说明的具名反面模式
- 模板测试：把产品名换成别的产品，这屏不成立（`craft.md` §1）
- 一屏只有一两处高光，外壳安静

### 讲价值
- 对比、方案、引导先用一个真实场景讲清「对我有什么不同」，功能清单在后
- 文案说的是结果（「训练改到 20:30，日历已改」），不是能力（「智能改期」）

### 状态完整
- 需求里要做的功能都有画板或写明无界面（`coverage.py`）
- 每个关键界面有：默认、第一次、空、出错、完成的那一刻；浅色和深色都看过（`verify_canvas.py`）

### 内容
- 真实、具体，有品牌声音，没有占位文案和空话

### 性能
- LCP < 2.5s、CLS < 0.1、INP < 200ms（能实测时以实测为准）
- 图片格式和尺寸合理，首屏关键资源优先加载

## 底线（不可让步）

- 文本对比度达标
- 可以用键盘操作，有可见的焦点样式
- 支持 reduced-motion
- 无横向溢出
- 图片有替代文本，标题层级正确，有页面语言声明
- 不使用虚构的数据、评价或客户 Logo
- 主操作在第一屏完整可见，不被底部输入区或标签栏挡住；文字加长 35%（换语言）以后仍然如此
- 画出来就能用：控件是真的 button / a href / label，只有图标的按钮有可读名称
- 画板验证结论为 done
