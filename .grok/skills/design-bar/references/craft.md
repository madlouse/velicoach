# 做稿与打磨的手艺（吸收 baoyu-design、unslop）

> 来源与授权：
> - **unslop**：Damir Sokolovsky（[@heydamir](https://x.com/heydamir)），CC BY 4.0。本文概括它的方向五行、九遍打磨顺序和模板测试，署名保留。完整技能在项目的 `unslop` 技能里时，打磨就直接按它走。
> - **baoyu-design**：JimLiu（https://github.com/JimLiu/baoyu-design ，自写部分 MIT）。本文概括它的做稿流程、验证者角色、写法规范和中日韩排版，用自己的话重写，不照抄。
>
> 用法：第 3.5 步做稿、第 5 步打磨和评审时读。

## 1. 先写方向，再动手（来自 unslop）

在 `brief.md` 的末尾写五行，每行一句。它们决定后面每一遍改动往哪个方向走：

| 行 | 写什么 | 不许写什么 |
|---|---|---|
| 产品 | 做什么、给谁，一句白话 | — |
| 气质 | 两三个具体的词，如「安静、准确、有一点暖」 | 干净、现代、简约、高级（每个模板都这么说） |
| 世界 | 产品天然属于的地方或材质，如「清晨的厨房、手写的训练本」 | 流行风格 |
| 高光时刻 | 每屏一到两处可以浓墨重彩的地方，从产品本身挑（一张画好的图、一个真实的物件） | 装饰性的光斑、渐变、玻璃 |
| 签名 | 只有这个产品会有的一个小细节，全产品一致地用 | 五个细节 |

**模板测试**：把产品名换成别的产品，这屏还成立吗？成立就说明方向推得不够狠，回到文案、视觉和签名去改。

## 2. 做稿：先摆出假设，再给选项（来自 baoyu-design）

- **先交一页「假设 + 依据 + 占位」**，像初级设计师向经理汇报：我理解的用户和任务、我打算怎么做、为什么；界面先用占位块。早给用户看，方向错了代价最小。
- **方向没定时给选项**：新界面、视觉方向不确定时，同一个问题给 2–3 个版本并排放在画布上（一个按惯例、一个有新意、一个折中），让用户挑或混搭；方向已定、只是补状态时不必。
- **设计扎根在已有的上下文里**：先找设计系统、已有组件、真实截图；从零画是最后的办法。缺素材时放干净的占位，比画一个差的强。
- **不加填充内容**：每个元素都要挣到自己的位置。空就是版式问题，用构图解决，不要编数字、编段落、加图标凑满（「数据填充」也是一种模板味）。想加内容，先问。
- **不画假的系统界面**：手机稿不画假的状态栏和键盘，留出安全区即可；画板里只有产品自己的东西。
- **选项要公平**：并排的选项每个都写一句真实的动机和主要代价（写在回复里，不写在画板上）；只给自己偏爱的那个讲理由，等于替用户投了票。选项一旦叫「方案 B」「安静版」，之后不改名、不重新编号。
- **定方向用低保真就够**：「决定要的保真度」低于「交付的保真度」。方向没定时用几块草稿画板比较结构和气质，定了再做高保真。
- **缺的事实用看得见的占位**：价格、日期、地址没定时写「[价格]」这类占位，不编一个看起来真的数字。
- **加东西之前先问**：觉得多一节、多一页、多一段文案会更好，先问用户；用户比你更了解受众。

## 3. 打磨：一层一层改（来自 unslop）

已有界面要去掉「AI 味」时，先按 `unslop` 的信号清单逐条审计，再判断改多少：

- **重度**（颜色、字体、图标、文案处处是信号）：按九遍顺序全改；
- **轻度**（大体有设计、残留几个信号）：只修审计出的，方向沿用现有品牌；
- **没有**：直说没有，最多提两三条带具体数值的小改，用户同意再动。

九遍的顺序（每一遍在整屏做完再进入下一遍）：**间距 → 颜色 → 图标 → 文案 → 字体 → 版式 → 细节 → 视觉 → 动效**。间距先做，因为节奏对了其他都会看起来不一样；文案在字体和版式之前，因为标题多长决定它多大、放在哪。

几条最常用的判断：
- **安静的外壳，浓的内容**：导航、按钮、文字只用中性色加一个强调色；颜色和质感留给一两个内容时刻。
- **一屏一个主操作**，最多再加一个次要操作。
- **同样的东西同样大**：列表行高一致、卡片内边距一致；组内近、组间远。
- **数字用等宽数字、同一种格式**；变化要写清和什么比。
- **动效只用来解释变化**：不循环、不弹跳、不动布局属性；一条缓动曲线、几档时长。

## 3.5 改动的范围：一类问题 vs 克制（两条原则怎么同时成立）

baoyu-design 说「小改动就只改那一处」，本技能又说「一条意见代表一类问题」。两条不冲突，分界在于**改的是不是同一个缺陷**：

- **同一类缺陷，全部改**：用户指出「这个按钮点不到」，所有同样小的按钮都改，规则写回设计系统。这是修 bug，不是自作主张。
- **不是同一类的「顺便优化」，只提不做**：改按钮时觉得旁边的卡片也可以更好看，写进交付的「建议」里，等用户同意再动。
- **用户只是在讨论**（「也许浅一点？」「这里有点空」）：继续聊、给两个小样，不改用户的文件；得到明确的「就这么改」或对你提议的「好」，再动手。

## 4. 写法规范（来自 baoyu-design，适合画板的 HTML）

- 每个非空元素显式闭合，属性值一律双引号，不自闭合非空元素；可编辑的文字放在叶子元素里。
- 兄弟元素之间的间距用 flex 或 grid 的 `gap`，不靠空白字符和外边距；行内排版只用于一句话里的链接和强调。
- 颜色从品牌和设计系统里取；确实不够时，用 oklch 在已有色板旁边推一个，不凭空发明。
- 不用 emoji，除非设计系统本身在用。
- 对比度：正文 4.5:1，大标题 3:1；4.3:1 也是不合格。最常出问题的是浅灰的说明文字和彩色底上的白字：两者都加深。
- **画出来就要能用**：静态稿也用真的 `<button>`、`<a href>`、`<input>` 加 `<label>`；不要在 div、span 上挂点击（Tab 到不了，读屏念不出来）；只有图标的按钮写 `aria-label`；装饰性的 SVG 加 `aria-hidden="true"`。
- **绑定写对**：生成脚本里不跳转的按钮就不写 `onClick`，别把空值写成 `{{ None }}`；f-string 里的花括号要成对转义（`{{{{ go1 }}}}`），否则变成一层 `{ go1 }`，点了没反应。验证器会报「交互绑定写错」。
- **要区分的颜色明暗也要不同**，不能只靠色相；需要两种状态色时，蓝和橙比红和绿安全。
- 兄弟元素用 flex 或 grid 的 `gap` 排，**不要让 flex 容器里的文字两头带空格**（会被吞掉，「还剩 3 天」变成「还剩3天」）；一句话里夹数字时，外层用 `inline-block`。
- 文字较多的地方用 `text-wrap: pretty`，避免末行只剩一个字。

## 5. 中日韩混排（来自 baoyu-design，补充 rubric 的排版项）

- 字体栈西文在前、中文在后：`-apple-system, "SF Pro Text", "PingFang SC", "Noto Sans SC", sans-serif`。
- 中文正文行高 1.7–1.8（比西文大），标题可以 1.3 左右。
- 给内容标 `lang="zh"` / `lang="en"`，浏览器才会选对字形和断行。
- 衬线阅读模式要给中文配宋体类的回退，否则中文会悄悄掉回黑体。

## 6. 验证：一个只读的验证者，只给结论（来自 baoyu-design）

做完一轮，先跑 `scripts/verify_canvas.py`（画板）或 `check_page.py`（真实页面），它扮演只读的验证者：

- **只报真问题**：主按钮被挡、文字挤成竖排、内容超出画板、对比度不够、触控太小、token 没定义、写死颜色、页面报错；不报审美意见。
- **只给两种结论**：`done` 或 `needs_work`，附位置和细节，制作者修完再跑，直到 `done`。
- **浅色、深色各查一次**：新组件常在深色下出问题（例如用了深色模式里也很深的品牌色做文字）。
- **换语言再查一次**（`--themes light,dark,pseudo`）：每段文字加长 35%，看主按钮会不会被挤出首屏。首屏刚好放得下的设计，换成英语一定坏。
- **报根因，不报像素**：按钮被挡、被挤扁时，原因通常是上面的内容不让出空间（flex 压缩、百分比高度没有参照），修内容和约束，不要只把按钮挪几个像素。
- **验证者自己也要被验证**：改了检查规则，先跑 `scripts/selftest.py`，它在一块故意做坏的画板上确认每类问题都抓得到、好的状态不误报。
- 审美和体验交给第 5 步的独立评审（或用户），两者不互相代替。

## 7. 评审意见写在稿子上（来自 baoyu-design 的 design-feedback）

- **只评看得到的**：没画出来的状态、静态稿里的悬停效果、只有一个宽度时的响应式，都说「看不出来」，不要猜。

给用户的评审，能贴在界面上就不要写成长文：每条意见钉在它说的那个元素旁边，一句「看到什么 → 为什么影响目标 → 往哪改」；第一组放最伤目标的问题，单列一组「做得好的、要保留的」，小毛病合成一组。用户只是在讨论（「也许浅一点？」）时继续聊，得到明确的「就这么改」才动用户的文件。
