# Velicoach 版式规范

本技能管 velicoach.com 主站和三站（站稳、看清、动手）的页面怎么排：骨架、版式、阅读排版、组件位置和交付检查。文字本身怎么写见 `velicoach-content` 技能；Veli App 和 Veli 网页版以 Veli 设计系统为准，不适用本技能。

## 1. 唯一来源

- **Velicoach 设计系统**（Claude Design 的 Design System 类型，链接见 `docs/uiue/design-system.md`）是颜色、字体、间距、圆角、玻璃、动效、断点的唯一来源。开工前先读它的 README，再读 `tokens.json`；仓库里的副本在 `docs/uiue/system/`。
- 需求以主站 PRD 为准（`docs/prd/velicoach.md`，在线文档是唯一来源）；设计上的取舍记在 `docs/uiue/decisions.md`。
- 样式只引用 token（`--vc-*`、`--space-*`、`--radius-*`、`--duration-*` 等），不写死颜色、字号、间距、圆角和时长。媒体查询里不能用 CSS 变量，断点写死同值并注明来自哪个 token。
- 需要新 token 或新规则时，先改设计系统，再同步到代码；不在页面里临时发明。
- 流程沿用 `design-bar` 技能：开工前确认关键信息与标杆，交付前跑检查，评审意见写回设计系统。

## 2. 开工前回答四个问题

1. **这页属于哪一站？** 决定底色、正文色、强调色和字体：站稳是纸色、无衬线、苔绿强调；看清首屏是墨色、衬线标题、朱砂强调；动手首屏是苔绿、无衬线、琥珀强调。强调色只在自己的底上出现。
2. **每一屏讲哪一件事？** 列出每屏的一句话；一屏讲不清一件事，就拆成两屏。
3. **这页的主动效是什么？** 首页是「叶与网」，分站只用几乎静止的纸墨质感，内容页没有主动效。
4. **读者在什么设备上读？** 文章页按手机优先排；首页按三档分别出稿。

## 3. 两步原则

**核心场景两步内完成，不常用的场景不超过三步。** 一步是一次有意的点按或提交；滚动和打字不算；系统弹出的账号选择算一步。逐个场景的步数表在 PRD 第 4 节「步数预算」，新页面、新功能先在那张表里加行，再出稿。

- **首屏就是操作台**：核心场景的入口都在第一屏，用户不需要先点一个按钮、再加载一个页面才找到要做的事。
- **按钮直达结果**：文字写点了之后得到什么（「进入今天的训练」「读本周文章」），点了就到，不经过介绍页；不写「了解更多」。
- **原地展开**：一个入口后面有几个去处时（例如「开始训练」：网页登录或下载 App），不跳到页面下方或另一页去选，在入口旁边直接给出选项，每个选项直达结果。有悬停的设备上鼠标停留 80ms 就展开，可以移进卡片，离开 300ms 收起，Esc 收起，悬停不算一步；键盘聚焦同样展开；触屏上选项直接摆在按钮的位置，手机上只给和系统对应的入口。悬停或聚焦时提前连接下一步的地址。悬停只是更快，不是唯一的路（WCAG 2.2 的 1.4.13）。只有一个去处的入口不做展开。细则见设计系统「原地展开」。
- **少一步的其他做法**：直达、卡片里直接操作、原地切换、卡片展开成页面（视图过渡加预先加载）、认出回来的人（一键登录、通行密钥）、记住选择、本站的操作条、撤销代替确认、搜索即命令。每种什么时候用、不采用哪些，见设计系统「少一步的做法」。
- **登录原地完成**：Google、Apple 按钮在当前页面弹出，登录后留在原页面并直接给出要做的事。
- **分清登录前后**：未登录给「开始」，已登录在同样的位置给「继续」（今天该练的、上次没读完的）；读到登录状态之前按未登录显示，位置预先留好，页面不跳动。
- **在对的时刻提示**：文章末尾给「今天的训练」，训练完成后给「本周文章」，两站互相带人。
- **不用操纵手段**：不倒计时，不用羞辱式的拒绝按钮，同意项不预先勾选；关掉任何东西只要一步。
- 交付时逐条走 PRD 的步数表，数出每个场景的实际步数，超出预算就改设计，不改预算。

## 4. 页面骨架

| 页面 | 从上到下 |
| --- | --- |
| 首页 | 首屏（站稳与看清左右拼接，「动手」圆在接缝上，叶与网）→ 一句宣言 → 三站各一张入口卡 → 本周：一读、一练、一件可以动手的事 → 订阅 → 页脚 |
| 分站首页 | 首屏标题和一句导语 → 本站的栏目（内容线）→ 最新内容 → 去另一站的入口 → 订阅 → 页脚；桌面和平板上另一站收成书脊 |
| 内容线列表 | 标题与一句说明 → 筛选（标签，不超过一行）→ 列表或时间线 → 分页 |
| 文章页 | 面包屑（站 / 内容线）→ 标题、作者、日期、授权说明 → 3 分钟视频 → 正文 → 原文链接 → 相关文章和今天的训练 → 订阅 |
| 开发日志 | 日期和项目 → 做了什么 → 和智能体的分工 → 截图或代码 → 下一步 |

每页都要有：顶部胶囊导航、页脚（站点地图、语言、隐私与条款、订阅）、加载中、空、出错、离线四种状态的样子。

## 5. 三种版式

按可用宽度分档，不按设备型号判断。

| 版式 | 宽度 | 边距 | 栅格 | 首屏 | 卡片 |
| --- | --- | --- | --- | --- | --- |
| 手机 | < 744px | `gutter-phone` 16 | 4 栏 | 上下拼接，「动手」圆压在接缝中央 | 单列 |
| 平板 | 744–1179px | `gutter-tablet` 32 | 8 栏 | 左右各半，两侧内容全部可见，不倾斜 | 两列，第三张占满一行 |
| 桌面 | ≥ 1180px | `gutter-desktop` 48 | 12 栏 | 左右各半，有悬停时可倾斜到 62 : 38 | 三列 |

- **悬停只是增强。** 倾斜、悬停才出现的说明只在 `(hover: hover) and (pointer: fine)` 下生效；触屏上所有入口和说明一开始就可见，点一下直接进入。
- **iPad 是一等公民。** 分屏、台前调度会把窗口变窄，版式随宽度落档；接触控板的 iPad 按桌面处理；横竖屏切换只重算尺寸，不重新加载动效。
- **手机细节**：首屏高度用 `100svh`；内容避开 `env(safe-area-inset-*)`；没有横向滚动（表格和代码块在自己的容器里横向滚动）；主按钮放在拇指够得着的下半屏。
- **字号随档位收紧**：主标题手机 44、平板 64、桌面 80；导语手机 17、其余 19；正文三档都是 16，不缩小。
- 页面内容最宽 `content-max` 1120px；正文最宽 `text-max` 640px。

## 6. 阅读版式（文章、开发日志、长说明）

阅读体验按「手机上一口气读完」来排。

- **行长**：中文每行 32–40 字（正文 16px 配 640px 宽）；英文每行 60–75 个字符。宽屏上不拉宽正文，多出的空间留白或放目录。
- **行高与段距**：正文行高 1.7；段距 24px（`space-5`），接近一行的高度；标题和上一段之间的距离是它和下一段之间的两倍，让标题贴近它管的内容。
- **字体**：中文正文用苹方和 Noto Sans SC；看清的标题用衬线（New York、宋体、Noto Serif SC），正文仍用无衬线，长文更好读；代码用 `font-mono`。
- **中英混排**：盘古之白由内容负责（`velicoach-content` 第 6 节），版式不靠 CSS 补空格；可以渐进地加 `text-autospace: normal`。标题用 `text-wrap: balance`，正文用 `text-wrap: pretty`，避免末行只剩一个字。
- **标题**：最多三级；手机上二级标题 24、三级 19。
- **代码块**：等宽 14px、行高 1.6；不自动换行，在块内横向滚动；右上角有「复制」按钮；标明语言。行内代码用浅底，不加边框。
- **表格**：放进可横向滚动的容器，首列固定；数字列右对齐并用等宽数字（`font-variant-numeric: tabular-nums`）。
- **图**：用 figure 和 figcaption；图注写清楚这张图说明什么、出处是哪里；图片按宽度自适应，给出宽高比避免跳动。
- **引用**：左侧 2px 强调色竖线，不用大引号装饰；引用原文时标明出处。
- **目录**：超过 2000 字的文章有目录。桌面上在正文右侧，随滚动吸附并标出当前小节；平板和手机上放在标题下方，默认收起。
- **3 分钟视频**：放在正文之前；播放条用厚玻璃；有字幕和文字稿入口。
- **文末**：原文链接、相关文章（最多三篇）、今天的训练、订阅，各自一行，不堆成推荐墙。

### 看清的页面

看清的气质是「工程师的书房：极简、克制、有品味」，来自陈皓的技术判断（学方法、没有捷径、知识要能被检索和更新），不照搬任何网站的样式。细则见设计系统「看清的气质」。做页面时：

- 首屏是一条墨色色带，只放站名、一句描述和两条内容线（AI 发展史、人机协作）；没有主图、动效和插画，不加载 three.js。
- 文章列表和里程碑一行一条：等宽的日期、标题、一句话，整行可点，行尾直接放「3 分钟视频」；不用卡片墙和缩略图。
- 学习路径和论文清单用能排序的表，表格只用横线。
- 引用用脚注；桌面版式把脚注放到正文右侧作侧注（`sidenote-width` 240px），手机和平板放回文末。
- 每篇标题下一行：发布日期、「适用于」（模型、版本）、最后核对日期；改过的在文末列更新记录；每个小节有锚点；文末有「指出错误」的入口。
- 学习路径每一步显示要花的大概时间和「怎么检验」；文章末尾的练习可以一步带到动手一站。
- 字体只用衬线标题、无衬线正文、等宽代码三种；颜色只用墨、纸、朱砂，朱砂只给链接和「当前所在」，链接加细下划线。
- 每条内容线有 RSS / Atom；不弹窗，读文章不需要登录。
- 文章页首屏只有文字，不依赖脚本也能读；除图片外一篇文章传输不超过 150 KB。

## 7. 组件与位置

- **胶囊导航**：常规玻璃，高 `nav-height` 52px；桌面上跨在首屏接缝上，其他情况居中贴顶。内容从左到右：叶子标识、三站入口（站稳、看清、动手；Body、Mind、Build）、搜索、登录（登录后是头像，点开是账号菜单）、语言切换。手机上搜索和登录只显示 44px 图标。三档都不用汉堡菜单。
- **语言切换**：导航最右端的分段控件「中文 | EN」，手机上「中 | EN」。选项用语言自己的名字，不用国旗；两个选项是指向对应语言版本的链接，带 `hreflang`，当前语言标 `aria-current`；切换后到同一页面的另一语言版本。支持三种语言后再换成地球图标加菜单。
- **书脊**：桌面和平板上进入一站后，另一站收成 56px 书脊，点书脊直接换站；手机上不放书脊。
- **按钮**：主按钮 50px 高、胶囊形，一个区域只有一个；首屏左右两半是两个区域，各有一个主按钮和两三个快捷入口。次要入口用文字链接或描边。可点元素至少 44px。
- **卡片**：用 `shadow-card`，不用玻璃；整张卡可点，标题是链接文字。
- **订阅框**：首屏底部一行「订阅」，点开后邮箱框原地展开，填完提交，两步；页面底部也有一个。下面一行说明频率和退订方式；提交后原地显示结果，不跳页。登录后同一位置是开关。

## 8. 玻璃

- 玻璃只给浮在内容上面的那一层：导航、浮层、播放条、「动手」圆。正文和卡片不用玻璃。
- 每块玻璃配 `shadow-glass`；背景模糊用 `blur-glass` 或 `blur-glass-thick`，同时把饱和度提到 180%。
- 不支持背景模糊或用户打开「降低透明度」时，换成 `vc-glass-fallback` 或对应的实色。
- 玻璃上的文字按最差的背景算对比度，至少 4.5 : 1。

## 9. 浅色与深色

- 全站默认跟随系统（`prefers-color-scheme`），系统切换时立刻跟着变；读不到时用浅色。
- 页脚和账号菜单里有「自动 / 浅色 / 深色」，搜索里输入「深色」也能切；按设备记住，`<head>` 里在绘制前设好主题，刷新不闪；设 `color-scheme` 和按主题的 `theme-color`。
- 品牌色带（首页两半、看清和动手的首屏）保持各站颜色，深色下首页左半用 `vc-hero-body` 的暗纸色；色带以下的阅读区、列表、卡片、表单都跟随主题。
- 颜色只用带浅色、深色两个值的 token；每个页面截浅色、深色两套图，两套都过 WCAG 2.2 AA。

## 10. 动效：「叶与网」

- 首页主动效是方案 C「叶与网」：Veli 的叶子由几千个点组成，桌面上首屏向右倾斜时散成一张网，向左时长回叶子；每个点的颜色取决于它落在哪一侧。没有悬停的设备上跟着呼吸周期（`duration-breath`）自动往返。
- 往下滚动可以延续「叶 → 网 → 搭起来的结构」的叙事，但同一屏只有一个主动效。
- 技术：three.js 的 WebGPURenderer 加 TSL，自动回退到 WebGL2；都不可用时显示静态画面。首屏文字绘制完再加载 three.js，不拖慢最大内容绘制。
- 预算：中端手机每帧不超过 4 毫秒，手机上粒子数减半；滚出视口或切走标签页时暂停；帧率持续低于 40 时把像素密度降到 1 倍。
- 系统打开「减弱动态效果」时只画一帧静态画面，倾斜也不做过渡。
- 界面过渡的时长和缓动只用 `duration-*` 和 `ease-*` token。

## 11. 双语版式

- 英文通常比中文长 30% 左右：不固定按钮和标签的宽度，用伪语言（加长 35%）截图检查，不截断、不溢出。
- 每页声明 `lang`；英文页面在 `/en/` 下，与中文页面一一对应并互相声明 `hreflang`。
- 英文标题用 sentence case，不全大写；字距沿用设计系统的英文设置。
- 同一个组件中英两版的高度可以不同，版式不能因此错位：列表和卡片按内容撑高，不写死高度。

## 12. 无障碍

- WCAG 2.2 AA：文字对比度至少 4.5 : 1；可点区域至少 44px；只用键盘能完成全部操作，Esc 让首屏回到五五分。
- 焦点环用 `vc-focus`，2px，向外偏移 2px；不去掉焦点样式。
- 系统字号放大到 200% 不截断；不只靠颜色表达状态。
- 动效画布对读屏软件隐藏；图表和插图有文字说明；短片有字幕和文字稿。

## 13. 交付检查

1. **多宽度截图**：覆盖三档和各档边界，375、744、820、1024、1180、1440 六个宽度，浅色、深色、伪语言各一套；手机和 iPad 再各截一张横屏。
2. **设计检查**（`design-bar` 技能的脚本）：
   - `check_page.py <页面路径或 URL> --out <报告目录>`
   - `lint_tokens.py <源码目录> --tokens <tokens.css>`：不能有写死的颜色、字号、间距、圆角和时长。
   - 改了画板：`verify_canvas.py <画板目录> --out <报告目录> --themes light,dark,pseudo`，修到结论为 done。
3. **去 AI 味**：按 `unslop` 的信号清单过一遍；和设计系统冲突时以设计系统为准。
4. **状态与降级**：加载中、空、出错、离线；关闭动效、降低透明度、减弱动态效果、无 WebGPU。
5. **性能**：手机 75 分位 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1。
6. **步数**：按 PRD 的步数表逐个场景数一遍，登录前、登录后各一遍。
7. **真机**：iPhone、iPad、Mac Safari、一台中端 Android 手机各走一遍关键路径。
8. 报告放进 `docs/uiue/reviews/<日期-主题>/`；交付时说明做了哪些体验决定和理由，记进 `docs/uiue/decisions.md`。

## 14. 改进规范

一条修改意见代表一类问题：找出背后的原则，改完所有同类页面和组件，再把原则写回设计系统（规则或 token）、本技能或检查阈值，并在设计决定记录里记一笔。不留下探索用的临时代码、未使用的样式和组件变体。
