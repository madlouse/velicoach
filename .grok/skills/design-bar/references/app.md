# App 交互设计

App 的质量要靠走流程来检验，而不是看单张屏幕。这份文件补充和替换主流程中的部分步骤。

## 第 1 步需要额外确认的信息

- 平台：iOS、Android 还是跨端；遵循 HIG 还是 Material 3（偏离规范时要写明理由）
- 3–5 个核心任务，以及每个任务的使用频率和场景（单手、通勤、专注工作）
- 用户是新手还是熟练用户；是否需要离线使用
- 有没有必须兼容的系统能力：通知、小组件、深色模式、动态字体、无障碍

## 第 2 步：参考拆解的重点

App 参考看的是流程，而不是截图里的视觉：完成一个任务要几步、空状态怎么引导、出错怎么恢复、转场怎么保持空间关系、哪里用了触觉反馈。

可以参考 Apple Design Awards 的类别来组织拆解，尤其是 Interaction（交互）和 Inclusivity（包容性）。

## 第 3 步之前：先做低保真流程

视觉方向之前，先交付（可以直接画在 Claude Design 的 Design 画布上）：

1. **任务流程图**：每个核心任务一张，包含返回、中断、出错的分支；
2. **状态矩阵**：每个屏幕的首次使用、空、加载、部分数据、错误、离线、无权限状态；
3. **导航模型**：标签栏、栈式导航还是模态，以及每个屏幕在模型中的位置。

请用户确认流程之后，再进入视觉方向。

## 设计系统 README 需要额外包含的部分

- 导航与层级规则
- 手势清单，以及每个手势的可发现性（是否有可见的替代操作）
- 转场规格：时长与曲线，或 spring 参数（damping、response）
- 触觉反馈的使用条件（只用于确认重要操作或边界）
- 反馈时机：100ms 内给出反馈；耗时操作用乐观更新或骨架屏；何时用加载指示器
- 键盘遮挡、安全区、横竖屏的处理

## 第 5 步：评审方式

### 走查
以新用户的身份，逐步完成每个核心任务，记录：
- 完成需要的步数和点击次数；
- 需要停下来思考的地方；
- 可能误触或无法撤销的地方；
- 出错后能否恢复。

同时对照 Nielsen 十条启发式原则检查。

### 渲染
- 用可点击的 HTML 原型，按目标设备尺寸渲染（例如 393×852、360×800）截图；
- 如果有原生工程，并且关联了本机，可以在模拟器里运行后截图；
- 每个状态都要截图，不能只看理想状态。

### 硬性指标
- 触控目标 ≥ 44pt（iOS）或 48dp（Android）
- 动态字体调到最大档时不截断、不重叠
- 适配安全区和刘海
- 深色模式单独校对
- VoiceOver 或 TalkBack 标签齐全，阅读顺序合理
- 常用操作位于单手可达区域
- 动效遵循系统的“减弱动态效果”设置

## 交付物

- 可点击原型
- 流程图与状态矩阵
- 设计系统（含 App 专用规则）与同步到代码的 tokens
- 开发交接规格（环境里有 design-handoff 技能时可以调用）
