# 搭一个多 Agent 开发团队

在 Velicoach 主站上第一次做成（2026-11-04，`docs/standards/pipeline.md`、`docs/delivery/`），机制复用 Veli 仓库已经在跑的流水线。下一个产品仓库照这里做。

## 原则

1. **复用，不重写**：引用参考仓库的一个固定提交，加一张「它的说法 → 本仓库的说法」对照表，只把不同的地方写全。不复制原文，否则两边会慢慢走样。参考仓库改了机制，由观察者每周对比，换版本号要人合并。
2. **关口在前，循环在后**：需求和界面没过对抗评审之前，不建定时任务。循环只放大已经清楚的东西。
3. **写和审分开**：每张票由新的子 Agent 做、另一个新的子 Agent 冷评审，评审换模型。
4. **每一段有人负责、有交接物、有人检查**：角色表里任何一段没人负责，或两方都以为对方负责，就是缺口。
5. **写进规范的每条命令都实际跑一次**：参数、宽度、文件、标签、issue 号逐个核对存在。

## 步骤

1. **读**：本仓库的 `AGENTS*.md`、PRD（阶段、版本范围、非功能需求、上线检查）、技能目录、`package.json` 的 scripts；参考仓库固定版本的 `AGENTS.md`、`docs/standards/`（pipeline、observer、agent-gitflow、quality-gates、spec-quality）、`.claude/agents/`、`docs/delivery/loops/`、经验库。在本仓库实际跑一遍测试和检查，记下基线是红还是绿。
2. **定关口**：对齐 PRD 的阶段。界面进代码之前的关口拆成两步：a 对抗评审（两个不同模型的独立设计评审 + 只读验证脚本，先有标杆卡）；b 拆成就绪的规格和票（冷审）。上线关口把 PRD 的硬性要求逐条列进去（端到端、性能、无障碍、真机）。
3. **定角色**：做事的、评审的、安全评审（只要收集任何用户数据就保留）、规格冷审、设计评审两份、日报、观察者。每个角色写模型和强度、负责什么、交接物、谁来查。
4. **定车道**：工作有几种性质不同的产出（代码、内容……）就分几条车道，**按文件**分工，写成表：哪条车道能改哪些文件，共享文件谁加结构、谁改文字。需求、技能、设计系统、画板的写回统一由主会话做。
5. **定循环**：每条车道一个推进器（心跳定时，拉起后连续推进），加日报和观察者；和参考仓库的定时错开。提示词放 `docs/delivery/loops/`，子 Agent 定义放 `.claude/agents/`。
6. **定分支和标签**：上线前一个集成分支，上线后直接进生产分支，门不变。标签照参考仓库；`owner:merge` 写清在本仓库的用法。Agent 写的每一条评论首行带机器人标记。
7. **定观察者**：复用参考仓库的观察者（目标函数、规则账本、归因顺序、权限、紧急刹车），加本仓库的抓手。设计和内容评审按 `design-bar`：独立评审不自评、只读验证者只给 done / needs_work、验证者自己也要被验证、有停止条件。给规范定篇幅预算。
8. **在 GitHub 上落地**：标签；状态 issue（总开关、运行锁、日报）；关口票；前置票（部署预览、集成分支、基线变绿、合并脚本、权限放行）。合并脚本由主会话写、人合并，不能由票自己写。
9. **冷评审这套机制**：派一个没参与写作的 Agent，给它两个仓库的路径和产品负责人的原话，让它查：新会话能不能照着跑、复用对不对、协作缺口、自相矛盾。改完再合并。
10. **记录**：用户原话进 `timeline.md`，理解和落点进 `trace.md`；开发团队怎么搭写进 `docs/delivery/team-setup.md`，开发路线写进 `docs/delivery/roadmap.md`。

## 踩过的坑（Velicoach 主站，2026-11-04）

- 基线测试是红的，流水线一开跑就会卡在「集成分支红了先修」。先把基线弄绿。
- 让第一张票自己写合并脚本：票的 PR 不能改门槛文件，等于自己判自己。改成主会话写、人合并。
- 以为「v1 没有登录就没有用户数据」，漏了订阅收邮箱，差点去掉安全评审。
- 只读验证脚本的参数、页面检查的宽度和主题写错；标杆卡还不存在就写进了停止条件。
- 只有运行锁评论带机器人标记，观察报告会被当成产品负责人的回复执行。
- 云端会话里 `gh api` 建分支（`git/refs`）被代理拒绝；用 `git push origin <本地分支>` 建。
- 画板用 `/_blob/<id>` 引用共享样式表，验证脚本读不到就误报一串；给 `verify_canvas.py` 加 `--blob <id>=<本地文件>`。

## 技能放在哪

技能在产品仓库的技能目录里迭代（主站是 `.grok/skills/`，`.claude/skills/` 放链接），仓库是唯一来源；账号里的同名技能是副本，仓库里改完再同步过去。
