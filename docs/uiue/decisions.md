# 设计决定

新的在上面。每条写清：决定、理由、改了哪里。产品层面的决定同时记在 PRD 第 10 节。

## 2026-11-04 · 画板里的「叶与网」用 WebGL2 直接画

- **决定**：画板首页的主动效用 WebGL2 直接画，约 6000 个点在叶子（主脉、侧脉、叶缘）和网（经线、纬线）之间变形：悬停站稳一侧收成叶子，悬停看清一侧展开成转动的网，不悬停时 10 秒一次呼吸；点的颜色按所在一侧取苔绿或朱砂，从 token 读。减少动态效果时只画一帧，滚出视野或切到后台时暂停。
- **理由**：画板不能从外部加载 three.js，上一版用静态圆点代替，看不出 C 的意思。原型要能看到真实的动态和悬停反馈，才能评审。正式站点仍按 ADR-0002 用 three.js（WebGPU 优先，WebGL2 回退），画板里的参数（点数、呼吸周期、颜色规则）就是实现的规格。
- **改了哪里**：画板 `Main`、`Tablet`、`Mobile`。平板和手机没有悬停，按设计系统「动效」一节只做呼吸往返；手机上点数减半，叶子放在接缝左侧，不压住文字和「然后动手」圆。

## 2026-11-04 · 内容打磨按模块单独跟进

- **决定**：画板 v1.0 作为起始版本，页面框架先不再改；内容分九个模块开票（首页文案、AI 发展史、学习路径、人机协作、文章模板、站稳内容、动手内容、订阅与分发、术语与英文版），每个模块先定选材标准、字段、模板和样稿，再进入每周运营。
- **理由**：产品负责人要求内容单独跟进、按模块定需求和方向；框架定下来以后，剩下的是运营的选材和生产。内容票不顺手改版式，放不下时另开界面票。
- **改了哪里**：GitHub #3 和子议题 #4–#12；`docs/issues/README.md`。

## 2026-11-04 · 看清的两条线和术语表

- **决定**：看清分两条线。AI 发展史以里程碑为主线，像科技史一样讲路线怎么转折，每个里程碑配能动手学的课程和代码，学习路径是按顺序排好的一页。人机协作讲人和 AI 一起工作的实践：工程（提示词工程 → 上下文工程 → Harness 工程 → Loop 工程 → Graph 工程）、团队与组织、个人，加上我们自己的开发日志。术语按行业通行说法，对外文案里 agent 写作智能体，没有通行译名的保留英文加一句白话；术语表分站点用语、AI 术语、不再用的说法三部分，并用 `npm run check:terms` 自动检查。
- **理由**：产品负责人明确看清的两个方面，要求术语符合行业标准、谨慎造词。原来的三条线里，学习路径服务于理解技术史，工程实践是协作实践的一部分，合成两条线更清楚。
- **改了哪里**：设计系统（两条内容线、用行业通用的词）；术语表；技能 `velicoach-content`、`velicoach-layout`；PRD 和总体方案；站点代码里的站名（页眉「看清 / Mind」、页面标题「看清 · Velicoach」）。

## 2026-11-04 · 看清的气质：从技术判断出发

- **决定**：看清的气质是「工程师的书房：极简、克制、有品味」。品味指对技术的判断：从陈皓的七个判断（学方法不只要答案、没有捷径、蛮力弥补不了眼界、从实践出发有观点、知识要被检索引用和更新、再轻的事也认真做、我不是高手）推出看清的产品做法：学习路径写清为什么学、学到什么程度、怎么检验、要花多久；按范式演进先给地图；每篇给判断、写代价；每篇标「适用于」和最后核对日期、有更新记录和纠错入口；每篇留一个能动手验证的练习，可以带去动手一站。页面上内容为主、界面退后，字体和颜色各三种，没有动效，文章页轻。
- **理由**：产品负责人指出「不是要抄他的网站，而是参考他的技术品味，根据我们的目标设计产品」。上一版把几个工程师博客的版式当成参照，这一版改为先列判断，再推出做法，页面样子是结果。
- **改了哪里**：设计系统「看清的气质」；技能 `velicoach-content`「看清的技术品味」、`velicoach-layout`「看清的页面」；PRD 内容字段（文章、学习路径步骤）和决定记录。

## 2026-11-04 · 专有名词用常见词，看清不另起刊名

- **决定**：三站仍叫站稳、看清、动手（Body、Mind、Build），三个站名就是口号「先站稳，再看清，然后动手」里的动作。看清不另起刊名，「同席」不再使用。其他名词用用户已经熟悉的词：订阅（Newsletter，按钮 Subscribe）、开发日志（Devlog）、大事记 / 学习路径 / 工程实践、今天的训练、3 分钟视频。
- **理由**：产品负责人要求名词按常见、用户能理解的说法并考虑国际化，同时确认「看清 / Mind」保留。中途一度把站名改成身体 / AI / 项目，产品负责人确认看清 / Mind 后改回。
- **改了哪里**：设计系统、术语表、PRD 和总体方案、技能 `velicoach-content` 与 `velicoach-layout`、本仓库文档。

## 2026-11-04 · 浅色与深色

- **决定**：主站和 Veli 都支持浅色、深色，默认跟随系统；读不到系统偏好时用浅色；页脚、账号菜单和搜索里可以手动选「自动 / 浅色 / 深色」，按设备记住。品牌色带保持各站颜色，深色下首页左半降成暗纸（新 token `vc-hero-body`，深色值 #33302a，和右半墨色的明度比约 1.4，上面文字对比约 11:1）；色带以下跟随主题。原来「看清页两种主题都是墨色」「首页首屏不随主题变化」两条作废。
- **理由**：产品负责人要求站点和产品都支持两种主题、默认跟随系统。网页通过 `prefers-color-scheme` 读得到系统设置，主流浏览器都支持，所以网页也默认跟随；读不到时选浅色，因为纸色是品牌主色，纸墨两半在浅色下对比最清楚，白天读长文也更舒服。切换是低频操作，不占导航位置。
- **改了哪里**：设计系统「三站，三种底色」「浅色与深色」、token；PRD F24、步数表、上线前检查；技能 `velicoach-layout` §9；Veli 仓库 issue #103。

## 2026-11-04 · 少一步的做法

- **决定**：在原地展开之外，再采用八种做法：直达、卡片里直接操作、原地切换（分段控件换内容，地址跟着变；列表原地追加）、卡片展开成页面（视图过渡加预先加载）、认出回来的人（Google 一键登录、通行密钥）、记住选择、本站的操作条（滚过首屏后顶部出现本站主操作，和 apple.com 产品页一样）、撤销代替确认、搜索即命令（⌘K 同时搜文章和操作）。
- **不采用**：左右滑动切站（和横向滚动、iOS 返回手势冲突，也看不出能滑）；长按预览（触屏上没人知道）；浮层打开文章（地址不能分享，搜索引擎看不到）；无限滚动（页脚到不了，不利于收录）。
- **理由**：产品负责人要求举一反三，穷举减少步数的方式并选最合适的。按「是否真的少一步、触屏和键盘能不能用、会不会伤搜索和分享」三条筛选。
- **改了哪里**：设计系统「少一步的做法」；PRD「步数预算」的登录行和「少一步的做法」一段；技能 `velicoach-layout` §3；Veli 仓库 issue #103（一键登录、主屏幕快捷入口）。

## 2026-11-04 · 原地展开

- **决定**：一个入口后面有几个去处时，在入口旁边直接给出选项，每个选项直达结果。有悬停的设备上停留 80ms 展开，悬停不算一步；键盘聚焦同样展开；触屏上选项直接摆出来，不需要先点开；悬停或聚焦时提前连接下一步的地址。用在「开始训练」、账号菜单、看清一侧的三条内容线。
- **理由**：产品负责人指出「和威利开始第一练」点了先滚到页面底部的卡片，再点才去应用商店，多了一步，建议悬停就出现卡片。采纳这个方向，但悬停不能是唯一的路：手机和 iPad 没有悬停，所以触屏上直接摆出选项；键盘和读屏也要能打开（WCAG 2.2 的 1.4.13）。
- **改了哪里**：设计系统「原地展开」；PRD「步数预算」的「开始训练」一行、新增「读某条内容线的新文章」一行和「原地展开」一段；技能 `velicoach-layout` 第 3 节；早期探索画布的「01 站稳」画板（首屏按钮、导航「开始」、页面底部的开始区）；Veli 仓库 issue #101 补充同一做法。

## 2026-11-04 · 两步原则

- **决定**：核心场景两步内完成，不常用的不超过三步。首屏就是操作台：左右两半各一个直达结果的主按钮加两三个快捷入口，底部一行订阅；导航加搜索和登录；登录在原页面弹出 Google、Apple；登录后同样的位置换成「继续」。
- **理由**：产品负责人要求进入主站或子产品首页后，操作尽量在两步内完成；只放一个按钮、点了再加载一个页面会多出一步。按 Fogg 行为模型，动机、能力、提示同时到位行为才会发生，所以入口要在第一屏、门槛要低、提示要在对的时刻。
- **改了哪里**：PRD 第 4 节「步数预算」、P4 验收、F01 验收；设计系统「一句话原则」「导航与语言切换」「版式」；技能 `velicoach-layout` 第 3 节。
- **待办**：Veli 落地页 `/body` 的同类修改（F146、S01，年龄确认并入 F141 同意页）见 Veli 仓库 issue #101。

## 2026-11-04 · 三种版式

- **决定**：按可用宽度分三档：手机 < 744px、平板 744–1179px、桌面 ≥ 1180px。首屏倾斜只给有悬停和精确指针的设备；触屏 iPad 横屏也保持左右各半、内容全部可见。
- **理由**：744px 是 iPad mini 竖屏宽度，1180px 是 iPad Air 横屏宽度；触屏没有悬停，靠悬停才出现的内容会被藏住。
- **改了哪里**：设计系统 token（断点、边距、导航高度）和「三种版式」；PRD F01、P6、非功能需求「多端」。

## 2026-11-04 · 语言切换

- **决定**：导航最右端放分段控件「中文 | EN」，手机上「中 | EN」；选项用语言自己的名字，不用国旗；支持三种语言后再换成地球图标加菜单。
- **理由**：只有两种语言时，分段控件一眼看到当前语言、一下切换；下拉菜单多一步，还把状态藏起来。
- **改了哪里**：设计系统「导航与语言切换」「语言版本的规则」；PRD F06、决定记录。

## 2026-11-04 · 首页主动效选 C「叶与网」

- **决定**：首页主动效用 C；A「墨入纸」降为分站几乎静止的纸墨质感；B「注意力」不用。
- **理由**：叶子是品牌签名，能延续成往下滚动的叙事（叶 → 网 → 搭起来的结构）；粒子网格是常见的「AI 感」，没有辨识度。产品负责人确认。
- **改了哪里**：设计系统「动效」；PRD 决定记录。

## 2026-11-04 · 建立 Velicoach 设计系统

- **决定**：主站单独一套设计系统，和 Veli 设计系统共用叶子、纸色、苔绿、主按钮和玻璃参数；苹果设计语言加毛玻璃，玻璃只给浮在内容上面的那一层。
- **理由**：主站有三站三种底色，Veli 只管其中一站；全站按苹果设计语言统一。
- **改了哪里**：新建设计系统；Veli 设计系统加入同一套玻璃 token（Veli 仓库 PR #96）。
