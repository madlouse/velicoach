## 2. 站点车道：里程碑草案

按「先把骨架和最常走的路做通，再补其余页面，最后做上线要求」排。每个里程碑结束时做一次里程碑关口（`pipeline.md` §4 ①）。

| 里程碑 | 范围（PRD 功能编号在拆票时补齐） | 退出条件 |
|---|---|---|
| M1 骨架 | 设计系统 token 同步进代码、页面骨架、导航与语言切换、浅色深色、三种版式、首页首屏和「叶与网」动效 | 首页三种版式 × 两种主题过 `check_page.py`；两步原则的首页操作走通 |
| M2 看清 | 看清首页（两条线、学习路径表）、文章页（3 分钟视频、旁注、练习、更新记录、纠错入口）、RSS | 文章页模板能承载 #8 定下的字段；关键路径「从搜索进文章」端到端通过 |
| M3 站稳、动手、订阅 | 站稳和动手两站的页面、订阅（邮件二次确认、退订、频率限制）、空状态和错误页 | 订阅的 PR 有安全评审通过；六种页面状态都有 |
| M4 上线要求 | SEO 与分享卡、监测、Lighthouse、axe、端到端补齐、真机走查 | 关口四（`pipeline.md` §2.3）全部通过 |

## 3. 内容车道

| 阶段 | 做什么 | 票 |
|---|---|---|
| 一 定框架 | 九个模块各定选材标准、模板和样稿，产品负责人合并就是确认。建议顺序：AI 发展史（#5）→ 学习路径（#6）→ 人机协作（#7）→ 文章模板（#8）→ 其余 | #3，子票 #4–#12 |
| 二 运营 | 按 PRD 第 6 节的每周节奏：周一选题、周二到周四生产、周五定稿、周六上线、周日订阅 | 上线后开始，每周的文章各开一张票 |

内容车道要的块类型或字段，由站点车道先做（M2 之前定好文章模板，#8）。

## 4. 两条车道的交汇点

| 交汇 | 先做 | 后做 |
|---|---|---|
| 文章页能放什么 | 内容 #8 定字段 | 站点 M2 实现文章模板 |
| 首页和三站的文案 | 站点 M1 放好位置和初稿 | 内容 #4 定稿文字 |
| 订阅邮件 | 站点 M3 做订阅 | 内容 #11 写模板和第一期 |
| 术语和英文版 | 内容 #12 定准入规则 | 两条车道都按术语表写 |
